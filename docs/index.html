Reading the Trace

Analytics logs what people do: clicks, pauses, going back. Product teams want to know what people are: confused, deliberating, engaged, gone. This project simulates a population of users moving through a checkout flow, then tests how much of their hidden state can be recovered from the trace alone, and where behaviour stops being informative.

How it works, and what it can't show

The simulated users

Each user has traits (tech fluency, carefulness, patience, distractibility) drawn around one of four personas. At every step they're in a hidden state (progressing, deliberating, confused or interrupted) that depends on the previous state, how clear the current page is to someone with their fluency, and their traits. The state then produces the logged action (forward, back, repeated click, off-path link) and the pause before it. Confused users can abandon, sooner if they're impatient.

The model

A four-state hidden Markov model, written from scratch in NumPy. Each step emits an action (categorical) and a dwell time normalised by page (Gaussian on log seconds). It's anchored on a small labelled sample and then fitted to unlabelled traffic by expectation-maximisation. It's deliberately simpler than the generator: its transitions don't know about pages or traits, so it's tested while misspecified, as a real model would be.

What this can't show

  • That real users behave like this. The generator is my set of assumptions about how states produce behaviour. The results show what's recoverable if behaviour works this way. They're a method check and a design tool, not evidence about people.
  • Real labels. Anchoring assumes you can code states in a small study. Real coding (think-aloud, in-the-moment probes) is noisy and changes behaviour, and that noise isn't modelled.
  • Live inference. Beliefs here use the whole session. Real-time detection would only have the past, and would be less accurate.

The obvious next step is to run the same pipeline on real sessions with sparse in-the-moment probes ("Are you finding what you need?"), and compare the model's posterior with the answers.
